### 1. 消融表 19 个数值与 176 题单次准确率不相容

位置：`main.tex:1266`、`1278`–`1296`，正文 `334`；相同表格见 `arr-Oct/ablation.md`。

论文写每个模型/条件在固定 176 题上只保留一次答案，准确率应为整数 `k/176`。枚举 0–176 个正确答案后，发现 **19/48 个单元格**不能四舍五入到稿中给出的一位小数；全部位于 C1/C3。

- DeepSeek-V3.2 C1 写 38.9%，但 68/176=38.6364%，69/176=39.2045%，分别应显示 38.6% 或 39.2%。
- Gemini-3.1-Pro C1 写 53.6%，但 94/176=53.4091%，95/176=53.9773%，分别应显示 53.4% 或 54.0%。

这不是表中“差值来自四舍五入”能够解释的问题。若有重复运行、非均匀加权或不同有效分母，必须据实重写协议、分母和结果来源。这里不预判具体原因。

本地另一组记录也存在实质差异：

| 单元格 | 论文 | 本地 `outputs/formal` 逐题预测重算 |
|---|---:|---:|
| DeepSeek-V3.2 / C1 | 38.9% | 72/176 = 40.9% |
| DeepSeek-V4-Flash / C0 | 34.7% | 61/176 = 34.7% |
| DeepSeek-V4-Flash / C1 | 30.6% | 75/176 = 42.6% |
| Gemini-3.1-Pro / C3 | 53.8% | 119/176 = 67.6% |

C0/C2 的论文数值与这套本地结果相符，但 C1/C3 多项不同。本地 C1 已有多模型超过 C0，不能支持稿中“12/12 模型均支持 C0”。这套本地记录也不一定是最终采用版本，因此不能直接拿它覆盖论文。

**人工责任人：实验负责人 + 不参与填表的复算者。** 找到实际入稿的每个条件、每个模型的逐题输出，核对题目清单、答案版本、模型、提示词与时间戳，并从冻结输出重新生成表、均值、检验和正文。若无法追溯，暂撤这些精确数字及显著性结论，不能靠调整百分比使其变得合理。

### 2. “221 道持续共同失败”与所写定义不匹配

位置：正文 `main.tex:375`；定义 `1425`。

附录定义为：一道题在 12 个模型 × 3 个记忆设置下全部答错。对现有 48 个主实验文件检查后，673 个题目 ID 和正确答案在各单元格对齐。按该定义重算得到 **34 道**，其中 Naive-RAG 至少 6 个模型选同一错误选项的有 **32 道，即 94.1%**；稿中对应数字为 221 道、84.2%。

**人工责任人：错误分析作者。** 明确 221 来自哪个阈值/哪个脚本/哪套预测，恢复精确定义并重新生成分母、混淆方向和图。不能把“多数模型失败”写成“全部模型失败”；上述 34/94.1% 也不能在最终实验版本未确认前直接替换。

### 3. 人工审计 κ=0.81、α=0.80 与声明的统计口径不相容

位置：`main.tex:1152`–`1183`，正文 `252`。

文中是同一批 176 题、3 人、无缺失、仲裁前的 A/B/C/D 选择。如果采用标准 Fleiss κ 和 **nominal** Krippendorff α，两者满足：

`α = 1 - (527/528) × (1 - κ)`。

因此 α 应略大于 κ；若 κ 恰为 0.81，α 约为 0.81036。即使考虑两位小数舍入，不能得到 κ=0.81 而 α=0.80。若用不同矩阵、不同版本、ordinal/interval 距离或其他实现，应查清并说明；A/B/C/D 没有有序距离，不能因为编码为 1/2/3/4 就当数值间距处理。

上述关系是由 complete nominal 数据下的标准定义推导；α 的原始定义见 [Krippendorff 的计算说明](https://www.asc.upenn.edu/sites/default/files/2021-03/Computing%20Krippendorff%27s%20Alpha-Reliability.pdf)。

**人工责任人：独立审计组织者 + 统计复核者。** 提供 176×3 原始选择矩阵、题目与选项映射、每位专家的独立记录、抽样清单/seed、计算代码及仲裁前后版本。若专家看到的选项分别打乱，应先映射回同一内容再算一致性。139 题全体支持、37 题两人支持本身并不矛盾；100% 多数支持也不能单独证明异常。

### 4. “只输入 content_full，ID/timeline 不可见”与现有 runner 不一致

论文位置：`main.tex:1206`–`1209`、`1436`。

代码证据：

- `agent-personality-benchmark/experiments/run_naive_rag.py:133`–`137` 拼接去除人格标签后的 memory ID、timeline、content_full，并保留 content_summary fallback。
- `agent-personality-benchmark/experiments/run_mem0.py:130`–`136` 拼接 mem_id、timeline 和提取后的 `memory` fact。
- `agent-personality-benchmark/experiments/run_personadb_mcq.py:120`–`124` 同样读取 `memory`，不是直接读取 content_full。
- 发布目录 `HEART-BENCH/experiments/scripts/run_naive_rag.py:140` 也保留 ID/timeline。

“存储/建库来源仅为 content_full”和“模型最终仅收到原始 content_full”是两个不同主张。Mem0 使用 fact 并不自动构成不合理，但必须准确描述。去掉人格标签的 ID 也不等于已证实存在人格泄漏；确认的问题是方法描述与可见代码不一致。

**人工责任人：runner 维护者。** 从正式运行保存的 request payload 抽取每种设置实例，建立输入字段表，记录实际语言、ID 去标识、时间信息、summary/fact 来源、截断和最大上下文预算。若论文对应更新后的实现，必须绑定该 commit 和重跑产物，而非只更新文字。

## P1：必须由人判断的有效性问题

### 5. 独立审计是否真正盲法、是否检验了模型可解性

位置：`main.tex:1152`、`1212`、`1109` 附近。

审计段只明确未展示模型来源和此前专家判断，未清楚交代：是否隐藏现有答案 key、审计专家具体看到哪些档案/记忆、是否允许“多项都合理”“信息不足”“无合适选项”，以及仲裁者所见材料。构建阶段完整 profile 的存在不等于模型的 top-30 记忆中存在足够线索。

稿件已在 `1212` 坦承信息不对称，因此不能再当成完全遗漏；剩余问题是尚无 matched-input 人类基线或 profile/oracle 对照，无法拆分“检索缺失、人格恢复失败、决策失败、选项歧义”。

**人工复核建议：** 对 37 道非全体一致题全部复核，并加入高模型分歧、共同错误、各角色/阶段的抽样。先给评审与模型完全相同的输入、隐藏 key，允许列出多个合理选项及“无法判断”；再提供完整 profile/更多记忆，检查判断变化。每次判断必须引用具体记忆句子。此建议属于新复核，不能描述成已完成的审计。

### 6. 人格极性与答案唯一性需要心理学专家逐题把关

位置：`main.tex:198`、`1142`–`1147`、`1194`–`1198`、`1425`。

11 个角色同时改变非锚定人格维度、职业、价值观和经历。因此“C-Low→C-High”是角色来源混淆，不能直接解释为模型弄反某个 Big Five 因子。论文已有相关限制，但图表、案例与结论仍需统一。

“内向所以独自投诉”“神经质所以紧张”的解释可能只是在识别合成文本中的刻板线索。人应判断：选项是否都满足场景约束；正确项为何更好；差别是行为、语用风格还是文字模板；不看记忆时是否也能凭显式性格描写选出答案。

**人工责任人：心理学专家 + 独立语言审阅者。** 对不同选项分别作可接受性判断，不只选择“最像”的一个。优先检查同一行动仅表达方式不同的题，以及高失败和相反极性混淆题。

### 7. 消融统计单位与干预含义还需加强

位置：`main.tex:1266`、`1296`、`334`。

稿中坦承只有模型级汇总，但本地存在 47 份逐题文件；先核实哪些适用于最终版本。12 个模型来自少数家族，不能未经论证当作独立、可交换的 12 个实验重复。按模型 sign-flip 得到的精确 p 值，不自动等于跨题目/场景泛化证据；“fixed panel”限定也不会自动满足统计假设。

应优先从最终逐题预测做场景配对的分析，固定模型面板，对 family 聚合/逐家族排除作敏感性检查。汇总舍入值不能充当原始样本。

**人工还需核对干预：** C1 的其他场景是否真不相关；C3 是否混入相关记忆；C2 的 donor 是否恰好对应一个干扰项角色；记忆长度、重复、情绪强度与年龄是否可比。换错角色后准确率下降可能包含 donor 选项吸引，不能唯一归因于预期的心理机制。

### 8. 专家参与与记忆质检的事实必须有记录支撑

位置：`main.tex:246`、`1071`–`1090`、`718`、`941`–`945`。

“每人 5+ 年”“教授 15+ 年”“约三分之一无需仲裁”“平均修改约 15% 词”“另一个独立专家组”等是可核实的事实，需要项目负责人核对人员资历、实际流程和记录。15% 应交代分词、编辑距离、分母、改写例子的计数方法和语言阶段。

记忆质检段承认缺陷/修复/人工检查数量未保留；不能把 11,000 条 schema 完整、文本非空视为心理合理性的证据。建议对最终记忆按角色、年龄、长度分层人工抽查，记录成人视角侵入、事件矛盾、过度病理化、模板复用、与 profile 不一致及未来知识。场景 DIAMONDS 评分应保存分歧解决前的两人评分，而不只展示协商后的分布。

### 9. 语言转换可能改变决策与标签

检查到现有实验 runner 使用中文提示词，论文给出英文模板，发布数据为英文。需要作者确认正式评测到底使用哪种语言，英文是否只是展示翻译，专家标注与仲裁发生在翻译前还是后。

具体抽查：发布文件 `HEART-BENCH-dataset/data/mcq.parquet` 中题目 `Q_CHAR_01_SCN_EARLY_ADULT_TRANSITION_6`，A/B 使用“three thousand yuan”，D 使用“three thousand dollars”；B 还明确提到 Alipay。同一场景的金额单位不一致，可能改变行为代价和合理性。

**人工责任人：双语作者/译审。** 核对金额、否定、行动承诺、语气强度、角色关系、心理描述以及正确项与干扰项的等价翻译，并保存中文与英文题目版本关联。该例证明发布数据存在需要译审的具体问题，不证明所有英文题有问题，也不证明它影响了中文实验分数。

## P2：补足报告严谨性

- **检索预算公平性（`1206`）：** “150 facts≈30 episodes”只是平均拆分比例，不能保证 top-k 实际信息量匹配。至少统计每题独立原始记忆数、去重率、输入 token、截断率与失败率；区分在各方法默认预算下比较和严格等预算比较。
- **API 可复现性（`1217`）：** 补充正式模型 ID、版本/日期、网关映射、逐模型请求参数、输出 token 上限与参数是否生效。temperature=0 只能降低采样变动，不能承诺严格确定性。结构化输出仍要求 rationale，需说明这是显式推理提示，而非完全没有推理。
- **时间信息：** 生成标注明确只激活 scenario 年龄以前的记忆（`1741`）；所有评测 backend 与 C1/C2/C3 是否执行同样限制，需要代码与请求证据。不能因论文未写而断言实际发生未来泄漏。
- **相关工作比较（`128`–`133`、`390`）：** PersonaMem 已包含从历史推断用户并进行个性化响应，PersonaLens 评测任务中的个性化表现。因此相关工作不宜笼统概括为仅事实或风格。可以精确区分“助手对用户个性化”和“代入角色选择其行为”，对比较表每个勾叉附原文依据。原始来源：[PersonaMem 官方仓库](https://github.com/bowen-upenn/PersonaMem)、[PersonaLens 官方仓库](https://github.com/amazon-science/PersonaLens)。这里不直接裁定所有叉号都错误。
- **主表数值一致性（`270`、`271`、`279` vs `1240`、`1241`、`1248`）：** 三处 0.372/37.1 的口径不一致，现有对应记录均为 250/673=37.1471%，按比例保留三位应为 0.371。所有表应从同一整数计数生成。
- **发布资料同步：** `HEART-BENCH-dataset/README.md` 仍称 human-like、orthogonal Big Five；当前正文已使用受控 persona consistency，并明确其他人格维度也变化。README 应同步，避免文稿收窄后数据卡继续过度主张。
- **单次选项随机排序（`1147`）：** 随机打乱能缓解位置偏差，不能保证消除。建议至少报告正确答案位置分布；若要声称鲁棒，补选项轮换或重排敏感性检查。
